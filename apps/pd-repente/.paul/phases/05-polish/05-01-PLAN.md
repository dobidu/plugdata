<objective>
## Goal
Auto-place programmatically created objects using a per-canvas cursor that cascades
positions instead of stacking at (100, 100); apply ObjectGrid snapping for grid alignment;
PatchMerger discards LLM coordinates in merge mode.

## Purpose
Currently every `/pds create osc~` (no x/y) and every PatchMerger merge lands objects
at (100, 100), causing pile-up that makes the patch unreadable. Auto-placement makes
REPL-created and merged patches immediately usable without manual rearrangement.

## Output
- `Executor::CanvasState` gains `placementCursor` tracking last auto-placed position
- `Executor::nextAutoPosition()` advances cursor, wraps at 700px → next row
- PDS_CREATE with no explicit x/y uses `nextAutoPosition()` instead of (100, 100)
- After creation + synchronise, `canvas->objectGrid.positionNewObject()` snaps to grid
- PatchMerger strips LLM x/y in merge mode — Executor auto-placement takes over
</objective>

    juce::Point<int> nextAutoPosition();

    Add `#include <juce_graphics/juce_graphics.h>` if not already present (for Point<int>).
    Check existing includes first — JUCE headers are often pulled transitively.

    ### Executor.cpp — implement nextAutoPosition()

    ```cpp
    juce::Point<int> Executor::nextAutoPosition()
    {
        auto pos = placementCursor;
        // Advance: 90px right; wrap at 700 → next row 60px down, reset x=50
        placementCursor.x += 90;
        if (placementCursor.x > 700) {
            placementCursor.x = 50;
            placementCursor.y += 60;
        }
        return pos;
    }
    ```

    ### Executor.cpp — save/restore cursor on canvas switch

    In `setCanvas()`, save and restore `placementCursor` alongside registry and nextId:
    - When saving old canvas state: `canvasStates[oldCanvas].placementCursor = placementCursor;`
    - When restoring new canvas state: `placementCursor = canvasStates[newCanvas].placementCursor;`
    - When initializing new canvas state: cursor defaults to `{50, 50}` (already set by CanvasState struct)

    ### Executor.cpp — wire into PDS_CREATE

    In the `CommandType::PDS_CREATE` case, change the x/y logic:
    ```cpp
    bool const hasExplicitCoords = (cmd.args.size() > 2);
    int x, y;
    if (hasExplicitCoords) {
        x = cmd.args[1].getIntValue();
        y = cmd.args[2].getIntValue();
    } else {
        auto pos = nextAutoPosition();
        x = pos.x;
        y = pos.y;
    }
    ```

    After `canvas->patch.createObject(x, y, objText)` succeeds and `canvas->synchronise()` runs,
    apply ObjectGrid snapping to the new object:
    ```cpp
    // Snap to grid if enabled
    if (!canvas->objects.isEmpty()) {
        if (auto* newObj = canvas->objects.getLast())
            canvas->objectGrid.positionNewObject(newObj, juce::Point<int>(x, y));
    }
    ```

    Note: `canvas->objects` is a `PooledPtrArray<Object>` (Canvas.h:219). `getLast()` may not
    exist on PooledPtrArray — use `canvas->objects[canvas->objects.size() - 1]` if getLast()
    is absent. Check Canvas.h for actual API; adapt accordingly.

    **Avoid:** Calling positionNewObject before synchronise — the Object* doesn't exist yet.
    **Avoid:** Advancing cursor when explicit coords are given (AC-2).
